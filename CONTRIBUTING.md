# Contributing

Thanks for helping improve the NodeRings provider. Bug reports, fixes, examples and documentation are all welcome.

## Developer Certificate of Origin

Every commit must be signed off, certifying that you wrote it or have the right to submit it under the project's license ([DCO](https://developercertificate.org/)):

```bash
git commit -s -m "Describe the change"
```

This adds a `Signed-off-by: Your Name <you@example.com>` line. Pull requests with unsigned commits cannot be merged.

## How this repository works

The provider is generated by [Upjet](https://github.com/crossplane/upjet) from the [NodeRings Terraform provider](https://github.com/noderings/terraform-provider-noderings), which is compiled in as a Go module. What a resource *does* (API calls, validation, retries) lives in the Terraform provider; how it appears in Kubernetes (names, groups, references) lives here.

| Path | What it is |
|---|---|
| `config/external_name.go` | Which Terraform resources are generated, and how their external names work |
| `config/groups.go` | API group, kind and cross-resource references of every resource |
| `config/provider.go` | Provider setup, root groups, in-process Terraform provider |
| `internal/clients/` | ProviderConfig credentials → Terraform provider configuration |
| `apis/`, `internal/controller/`, `package/crds/`, `examples-generated/` | Generated. Do not edit by hand |
| `examples/` | Hand-written examples, also used as end-to-end tests |

## Making a change

1. Install Go (see `go.mod`), Docker and `goimports`, and clone with `--recurse-submodules`.
2. Make the change in `config/` or `internal/`.
3. Regenerate and check everything CI checks:

   ```bash
   make generate
   make reviewable
   ```

4. Commit the generated files together with your change, signed off, and open a pull request.

A new resource in the Terraform provider fails `make test` until it has an entry in `config/external_name.go` and `config/groups.go`.

## Tests

- `make test` runs the unit tests. No account is needed.
- `make e2e` deploys the provider to a local kind cluster and runs the examples against the live NodeRings API. It needs `UPTEST_CLOUD_CREDENTIALS` set to `{"token":"..."}` for a test service account; see the README.

Examples that create billed resources say so at the top of the file. Use a test organization with a credit limit.

## Releases

Maintainers run the **Publish Provider Package** workflow with a version such as `v0.2.0`. It pushes the package to `ghcr.io/noderings` and `xpkg.upbound.io/noderings`.
